    Class webcoder31\ezxmldsig\X509Cert

    Analyze an X.509 certificate. The X509Cert class provides a set of convenient methods for extracting essential information contained in an X.509 certificate and for performing some useful checkings. Every cryptographic check (signature of the certificate, chain of trust, validity dates) is performed by OpenSSL. This class is used internaly by the XMLDSigToken class.

    public isTrustedBy(string|array $caCertPaths): boolean

    Check that the certificate is trusted: OpenSSL builds and verifies its chain up to a certificate of the given CA files. Every certificate of the given files is trusted, and the chain is built from these certificates only. OpenSSL verifies the signature of each link, the validity dates of every certificate of the chain at the current date, that each issuer is a CA (basic constraints, key usage, path length) and that the chain ends at a self-signed certificate of the given files. A chain that stops at an intermediate CA is rejected: to trust the certificates issued by an intermediate CA, give its certificate and the certificates up to its root (in one file or in several). A certificate issued by another intermediate CA of the same root is then rejected, since the chain cannot be built without that other intermediate certificate.

    public isValidCA(string $caCert): boolean

    Check the origin of the certificate. Verify that the X.509 certificate has been issued by the given CA certificate: OpenSSL verifies the signature of the certificate with the public key of the CA certificate, the issuer name of the certificate must be the subject name of the CA certificate, and the CA certificate must be a CA ("CA:TRUE" basic constraint and, if it has a "keyUsage" extension, "keyCertSign"). Only this link is checked: neither the validity dates nor the chain of the CA certificate. Use isTrustedBy() to verify the whole chain. NOTE : Note that more than one CA certificate can give a positive result, some certificates re-issue signing certificates after having only changed the expiration dates. Note that it also works with self-signed CA certificates. In this case, passes the X.509 certificate itself to the function.
